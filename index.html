AI as a command

Pipe data in. Tell it what to do. Pipe results wherever you like.

The model, your data, nothing else

Work with any LLM like a normal shell command: ai run "explain this", pipe data in via stdin, and pipe the response out wherever you need it. Bare ai starts an interactive session. The AI sees only what you give it — no filesystem, no network, no shell unless you grant it — and every capability beyond a plain answer is an explicit, independently gated choice. Local semantic memory is on by default and can be turned off with --no-memory.

File access: off Shell: off Web: off Declarative policy engine Runs fully local for memory
Capabilities you opt into
🌐

Web Access

Search the web through a configurable provider ladder (Brave, Tavily, Exa, Serper, SearXNG, or keyless DuckDuckGo/Google/Bing). Fetch any URL and convert HTML to readable text, all gated with URL allowlists.

💻

Browser Automation

Navigate, click, extract — drive a stealth headless browser for JavaScript-heavy sites, login flows, and dynamic content. Requires web-fetch permission.

📁

Filesystem Access

Read-only or read-write with fine-grained permissions. Paths are resolved (symlinks included) before policy, so deny rules inside an allowed tree hold. Policy files and interactive ask mode.

$>

Shell Commands

150+ built-in commands (grep, sed, awk, find, tar, curl, git, …) run in-process via bashkit. Only external commands need allowlisting, and read/write policy still governs the files they touch.

📦

Container Isolation

Run external commands inside a session container (-X). Only the policy-granted paths are bind-mounted, and it gets no network unless web access is granted.

🧠

Semantic Memory

Facts and past exchanges are embedded locally (ONNX) and searched with sqlite-vec. Relevant hits are injected per message with a match score — no API round-trips, no data leaving your machine.

🌙

Memory Maintenance

ai dream distills conversations into durable facts, prunes stale transcripts, and reviews old entries. Run it on demand, automatically at session end, or schedule it.

📜

Skills

Drop a SKILL.md into the skills folder and the model can load it on demand, along with any bundled scripts and docs. With skills.auto_create, ai dream can even author skills from your past sessions.

💾

Persistent Sessions

Conversations auto-saved to disk with the full tool history. Continue the newest one automatically, resume by date-aware name, fork on a provider/model change, or run stateless.

⚙️

MCP Tool Servers

Connect external MCP servers via --tool URL or mcp.servers in the config. IDE integrations, database agents, API gateways — a bad config entry warns and is skipped.

✨

Two-Phase Setup

ai setup walks you through a provider and model (browsing the models.dev catalog), proves the connection, then lets the AI finish the config through a sandboxed, approval-gated edit.

📖

Inline Help

Ask the agent about ai itself — commands, flags, config keys, behavior — and it answers from a built-in manual instead of guessing. Shell completions included (ai completions).

$> curl -fsSL https://dswd.github.io/ai/install.sh | sudo sh -s -- --global
