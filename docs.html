Documentation

Everything you need to use ai effectively. From your first prompt to advanced policy configuration.

Overview

ai is a CLI copilot that turns any LLM into a shell command. Pass a prompt on the command line (or pipe data in via stdin), and the response streams to stdout. Tool calls and thinking output go to stderr, so you can pipe results cleanly into other commands.

By default, the model sees only what you give it — no filesystem, no network, no shell. Every capability beyond that is opt-in via CLI flags or a declarative policy file.

Providers: Supports OpenAI and Anthropic natively, and any OpenAI-compatible API (Ollama, Groq, DeepSeek, Google Gemini, Mistral, OpenRouter, xAI, llamafile) via api_base.

Quickstart

$ ai "explain this regex: ^(?=.*[A-Z])(?=.*\d).{8,}$"
$ cat data.csv | ai "summarize the trends in this CSV"
$ ai -x=cargo,git -r=./src/** -w=./src/** "fix all compiler warnings"
$ ai --init

Examples

# ask a question (vanilla mode — no tools) $ ai "what does the borrow checker enforce?" # give it filesystem access $ ai -r=./src/** "refactor the auth module" $ ai -w=./src/** "add input validation to handlers.rs" # allow specific commands $ ai -x=cargo,git "build and check for warnings" # web access $ ai --web "what changed in the latest Rust release?" $ ai --web-fetch=https://docs.rs/** "summarize the serde docs" # interactive session $ ai -s=my-project -r=./** -w=./** -x=cargo,git,npm # pipe data in $ cat error.log | ai "find the root cause of these errors" $ git diff HEAD~5 | ai "summarize the changes and suggest a release note"

Configuration

Config is stored as YAML at ~/.config/ai/config.yaml. Every field is optional; CLI flags and env vars override config values.

provider: openai api_key: env:OPENAI_API_KEY model: gpt-4o api_base: https://api.openai.com/v1 system_prompt: You are a helpful CLI assistant. context_window: 128000 max_tokens: 4096 thinking: 16000 session_dir: ~/.local/share/ai/sessions policy: ~/.config/ai/policy.conf memory: ~/.local/share/ai/memory.json

Providers

ai speaks the OpenAI and Anthropic APIs natively. For any other provider, set api_base to their OpenAI-compatible endpoint.

# Ollama (local) $ ai -c=ollama.yaml "explain monads" # OpenCode (OpenAI-compatible) $ ai -c=opencode.yaml "write a fibonacci function"

Example configs

# ~/.config/ai/openai.yaml provider: openai api_key: env:OPENAI_API_KEY model: gpt-4o
# ~/.config/ai/ollama.yaml provider: openai api_base: http://localhost:11434/v1 api_key: ollama model: llama3.2
# ~/.config/ai/anthropic.yaml provider: anthropic api_key: env:ANTHROPIC_API_KEY model: claude-sonnet-4-20250514

Access Policy

The policy engine controls what files, commands, and web resources the model can access. Rules are evaluated first-match: the first matching Allow or Deny rule wins. CLI flags (-r, -w, -x, --web) are prepended to policy-file rules and always take precedence.

Actions

ActionCovers
readread_file, list_dir, search_content, find_files, file_info, file_view, git_diff, git_log
writewrite_file, replace_in_file, delete_file, create_directory, move_file, copy_file
executeexecute
web-fetchweb_fetch, download_file
web-searchweb_search

Policy File Syntax

One rule per line. # starts a comment.

# grant read access to the home projects directory allow read ~/projects/** # deny access to secrets subdirectories deny read ~/projects/**/secrets/** # allow specific commands (comma-separated) allow execute cargo,git,npm,npx,rustc # allow web fetch from docs.rs allow web-fetch https://docs.rs/** # deny search queries containing "confidential" deny web-search *confidential*

Path Matching

Path patterns support glob wildcards and are segment-aware: /tmp matches /tmp/foo.txt but not /tmpfile. Relative patterns resolve against the home directory. ~ is expanded.

Execute Patterns

The execute tool is always available. 164 built-in commands (echo, cat, grep, sed, git, curl, …) run inside a virtual bash interpreter (bashkit) and are governed by filesystem read/write policy, not execute permissions. Only external commands (e.g. cargo, npm, python) are checked against the execute allowlist.

Example: With allow execute cargo, running cargo build is allowed (external command) but cat Cargo.toml needs allow read Cargo.toml (builtin, FS policy). Running rm -rf / needs allow write /. Builtins like echo, ls, grep follow the same FS policy — they check read/write on the files they access, not execute on their name.

Interactive Ask Mode

With -i, when a tool wants to access a resource not covered by any Allow rule, you'll see:

$ ai -i "fix the bug"

❓ Allow Read for /home/user/project/src/auth.rs? [y/N]

Type y or yes to allow once. Anything else denies the access.

Sessions

Sessions persist conversations to disk as JSON files. Each session records every message, the system prompt, model, and timestamps.

# start a named session $ ai -s=backend-refactor -r=./** -w=./** -x=cargo,git # resume it later $ ai -s=backend-refactor # random name generation $ ai -s # → created session "calm-lynx" # list all sessions $ ai -l # delete a session $ ai --delete=calm-lynx

In-Session Commands

CommandAction
/exit, /quitExit the session
/clearClear all messages in the session
/compactSummarize the conversation and replace history with the summary to save tokens
/sessionPrint the current session name
/toolsList available tools
/helpShow all slash commands
Context tracking: When context_window is set in config, the interactive prompt shows token usage: [4.2k/128k] >. A warning emoji (⚠️) appears when usage exceeds 75%.

Memory

Persistent key-value store that the model reads at the start of each conversation. Entries are injected into the system prompt. The model can add and delete entries itself via tools.

$ ai -m "remember that our API uses snake_case" # custom memory file $ ai -m=~/.ai/project-memory.json "refactor the auth module"

Keys are 4-character hex strings (e.g. 0a1f). The model manages entries via two tools: memory_add and memory_delete. Max 100 entries.

Placeholders {memory} and {timestamp} in the system prompt are replaced with the current memory contents and date/time.

MCP Tool Servers

Connect to Model Context Protocol servers to extend ai with external tools — IDE integrations, database agents, API gateways.

$ ai -t=http://localhost:8080/mcp "what tables are in the database?" # multiple servers $ ai -t=http://localhost:8081 -t=http://localhost:8082 "query the inventory"

Discovered tools are automatically registered on the agent and available for the session.

Built-in Tools

25 built-in tools are conditionally registered based on active policy rules.

Filesystem

read_file

Read file contents. Supports offset and limit for pagination.

path offset? limit?

write_file

Create or overwrite a file. Creates parent directories automatically.

path content

list_dir

List directory contents with type prefixes (d directory, l symlink, f file).

path offset? limit?

replace_in_file

Surgical string replacement. Old string must match exactly once — fails on zero or multiple matches.

path old_str new_str

delete_file

Delete a file or directory. Directories require recursive: true.

path recursive?

create_directory

Create a directory and all parent directories (like mkdir -p).

path

file_info

Get file or directory metadata: size (human-readable), permissions (r-- or rw-), modification time, and type.

path

move_file

Move or rename a file or directory. Checks write permission on both source and destination.

source destination

copy_file

Copy a file to a new location. Creates parent directories as needed. Checks read on source, write on destination.

source destination

file_view

Extract readable text from rich documents by converting them to Markdown via markitdown. Supports PDF, DOCX, XLSX, PPTX, HTML, CSV, XML, images, and ZIP archives.

path

Execution

execute

Run a shell command. 164 built-in commands (echo, cat, grep, sed, git, etc.) run in-process via bashkit — no forking. External commands fork-exec as needed. Filesystem access governed by read/write policy.

command cwd? offset? limit? timeout?

git_diff

Show uncommitted changes with git diff --no-color. Supports --staged and file-path filtering. Requires read access to the .git directory, not shell execution permission.

staged? path? offset? limit?

git_log

Show commit history with git log --oneline. Requires read access to the .git directory, not shell execution permission.

n? path? offset? limit?

Search

search_content

Regex search across files. Skips hidden directories (.git, node_modules, target) and binary files. Max 500 matches, 1 MB per file.

path pattern file_types? offset? limit?

find_files

Glob-based file search. Results sorted alphabetically, truncated at 500.

path pattern offset? limit?

Web

web_fetch

Fetch a URL and return content as text, markdown, or HTML. HTML is converted to readable text via html2text. Max 5 MB response.

url format? timeout? offset? limit?

web_search

Search DuckDuckGo, Google, and Bing via stealth headless browser. Returns results with titles, URLs, and snippets. Max 20 results.

query num_results? offset? limit?

download_file

Download a file from a URL and save it to disk. Max 5 MB. Requires write permission on the destination path.

url path

Browser

browser_navigate

Navigate the browser to a URL. Returns the page title and content size. Requires web-fetch permission on the URL.

url

browser_click

Click an element by CSS selector on the current page. Navigates to a URL first if provided.

selector url?

browser_get_content

Get the full page content in markdown or raw HTML. Requires a prior navigate call.

format? offset? limit?

browser_get_element

Extract a specific DOM element by CSS selector in markdown or raw HTML.

selector format? offset? limit?

browser_evaluate

Execute arbitrary JavaScript on the current page and return the result as JSON.

Other

memory_add

Store a fact in persistent memory. Returns a 4-char hex key. Only available when -m is active.

data

memory_delete

Delete a memory entry by its key. Only available when -m is active.

key

Vanilla Mode

Running ai with no flags and no config file drops you into vanilla mode: the model sees only your prompt and responds with plain text. No tools are registered. No filesystem, no shell, no web.

$ ai "what is the time complexity of quicksort?"

This is the safest way to use ai. Every capability beyond this is an explicit opt-in.

Quiet & Verbose

# quiet: no thinking output, no token stats $ ai -q "what is 2+2" # verbose: debug-level logging $ ai -v "explain this code"

Quiet mode suppresses the thinking/reasoning stream and token usage summary. Verbose mode enables full debug logging from the ai:: module.

Extended Thinking

Enable extended reasoning with a token budget. Supported by Anthropic models and some OpenAI models.

# default 16k thinking tokens $ ai --thinking "design a distributed rate limiter" # custom budget $ ai --thinking=32000 "audit this codebase for security vulnerabilities"
Note: Thinking tokens are counted in the token stats but excluded from the visible output count. Stats are shown as (in, thinking, out) where out = output_tokens - reasoning_tokens.

Init Wizard

The --init command runs an interactive setup wizard that walks you through provider selection, API key entry, model choice, and context window configuration.

$ ai --init Provider: [openai] anthropic ollama groq deepseek google mistral openrouter xai API key (OPENAI_API_KEY): ******** API base URL (optional): Model: [gpt-4o] gpt-4.1 gpt-4.1-mini gpt-4o-mini Other (type manually) Context window (tokens, 0 to skip) [128000]: Save this config? [Y/n]

If you leave the API key blank and a corresponding env var exists, it will be stored as env:VAR_NAME rather than the actual key.
